## 2. Binding, transport, auth, registration (all proven by disassembly)

- Protocol sequence `ncalrpc`, endpoint `HumanPresenceDetectionEndpoint`
  (UTF-16 strings at LnvSST.dll rva 0x34f60/0x34f70; client composes the same via
  `RpcStringBindingComposeW`/`RpcBindingFromStringBindingW`).
- **Auth level: none.** Neither DLL imports `RpcBindingSetAuthInfo*` /
  `RpcBindingSetAuthInfoExW` / `RpcBindingSetOption(security)`. The binding is used as
  `handle_t` directly; the server calls `RpcImpersonateClient`/`RevertToSelf`
  for the local caller's token. This is not anonymous authorization: the ALPC
  endpoint DACL and the per-call token/context checks still apply.
- Server start (`HPDRpcServerStart`, around LnvSST.dll 0x14800–0x14a70):
  1. Five `EXPLICIT_ACCESS_W` entries are zero-initialized on the stack, each with
     `GENERIC_ALL (0x10000000)`, `SET_ACCESS (2)`, no inheritance and `TRUSTEE_IS_SID`.
     Four `AllocateAndInitializeSid` calls plus one derived capability supply:
     - `S-1-2-0` (LOCAL): authority bytes `00 00 00 00 00 02`, one RID 0;
     - `S-1-5-11` (Authenticated Users): NT authority, one RID 11;
     - the capability SID from `DeriveCapabilitySidsFromName(L"Lenovo.smartSense_k1h2ywk1493x8", ...)`;
       exactly one capability SID is required and the first is used;
     - `S-1-5-32-544` (Builtin Administrators): NT authority, RIDs 32/544;
     - `S-1-5-18` (LocalSystem): NT authority, RID 18.
     `SetEntriesInAclW(5, ...)`, `InitializeSecurityDescriptor(...,1)` and
     `SetSecurityDescriptorDacl` create an **absolute SECURITY_DESCRIPTOR**, passed
     by address to both endpoint and interface registration. Evidence: 0x147a8–0x149c5.
  2. `RpcServerUseProtseqEpW(L"ncalrpc", MaxCalls = 10 + ret(SetEntriesInAclW),
     L"HumanPresenceDetectionEndpoint", &SD)` — success path MaxCalls = 10.
  3. `RpcServerRegisterIf3(IfSpec = &RPC_SERVER_INTERFACE @ rva 0x33c30
     {848A33AC-B5A7-4253-A54F-E0AC20648468} v1.0, MaxCalls = 0x4d2 (1234),
     MgrTypeUuid = NULL, MgrEpv = NULL, Flags = 0x21, MaxRpcSize = 0,
     SecurityCallback = NULL, SecurityDescriptor = &SD)`
     → `RPC_IF_AUTOLISTEN | RPC_IF_ALLOW_LOCAL_ONLY` on success.
  4. `RpcServerListen(1, 0x4d2, 1)`; return `0x6b1` (RPC_S_ALREADY_LISTENING) accepted
     as success because AUTOLISTEN already started the listener.
- `MIDL_SERVER_INFO @ 0x33bd0`: nCount = 2 — NDR v2.0 (`8A885D04-1CEB-11C9-9FE8-08002B104860`)
  first, NDR64 (`71710533-BEBA-4937-8319-B5DBEF9CCC36` v1.0) second. Both registered;
  **NDR32 tables below are fully decoded and are sufficient** (server accepts NDR32).

Per-call authorization is separate from endpoint admission. Handler helper 0x13300
opens the impersonation token and checks enabled Administrators, LocalSystem, and
the derived capability SID; these mark the context privileged. Authenticated Users
may pass the read-level check without that privilege. The setter context check
0x13210(ctx,1) requires either the privileged flag or the process-validation flag
captured at initialization. Initialization obtains the local client PID and calls
`Lenovo.AssemblyValidation.Native.dll!ValidateAssembly` indirectly on its process
image (0x12e44 → 0x16bfc → 0x16ab8). The owned client does **not** load that DLL or
spoof a signed process. Use an elevated authorized native CLI for write acceptance;
ordinary-user write admission is not promised. The server/driver still owns its
validation dependency; a client-library cutover does not remove server dependencies.

## 3. NDR32 interpreter tables (both DLLs byte-identical)

| Table | Server (LnvSST.dll) | Client (SmartSenseRpcClient.dll) |
|---|---|---|
| Proc format string | rva 0x33782 | rva 0x17ed2 |
| FmtStringOffset | rva 0x32b20 (20 primary + callback) | rva 0x186c8 (21 primary) |
| Type format string | rva 0x33742 | rva 0x18612 (MIDL_STUB_DESC +0x40) |
| MIDL_STUB_DESC | 0x33c90 | 0x183b0 |
| RPC interface spec | 0x33c30 | 0x17dd0 |

Per-record layout (-Oicf, x64): `u8 handle_type; u8 Oi_flags(0x48); u32 rpc_flags;
u16 proc_num; u16 stack_size`; then the explicit handle descriptor at +0x0a
(4 bytes for `FC_BIND_PRIMITIVE` on op0, 6 bytes for `FC_BIND_CONTEXT` otherwise),
the 6-byte partial OIF header, the 10-byte EXTS64 block, and 6-byte parameter records
`{u16 attrs; u16 stack_offset; u16 type}`. Parameters start at +0x1e for op0 and
+0x20 for context-bound operations. `stack_size` includes the return slot.

Empirical PARAM_ATTRIBUTES: IS_IN=0x08, IS_OUT=0x10, IS_RETURN=0x20, IS_BASETYPE=0x40, IS_SIMPLE_REF=0x0100,
[in,out] ctx=0x0118; [out] simple-ref u32 = 0x2150; [out] unique must-size/must-free =
0x2013; return = 0x70 with type 0x0b. Type field: inline FC (0x08=FC_LONG, 0x0b=FC_HYPER)
or TFS byte offset. TFS anchors: +0x06 BIND_CTX(a4), +0x0e BIND_CTX(e5), +0x12 BIND_CTX(45),
+0x16 RP→FC_LONG, +0x1a RP→FC_HYPER, +0x1e RP→UP→FC_CARRAY of `FC_WCHAR`
(2-byte elements, alignment-minus-one 1). Its robust correlation is
`TOP_LEVEL_CONFORMANCE|FC_ULONG`, `FC_DEREFERENCE`, stack offset 0x78, Early=1:
`size_is(*p15)`. TFS +0x34 is `FC_C_WSTRING`.

Public metadata grammar references: [Microsoft pointer descriptors](https://learn.microsoft.com/en-us/windows/win32/rpc/pointers-tfs),
[correlation descriptors](https://learn.microsoft.com/en-us/windows/win32/rpc/correlation-descriptors-tfs),
and [public PARAM_ATTRIBUTES/FC definitions](https://github.com/reactos/reactos/blob/master/sdk/include/psdk/ndrtypes.h).
The owned generator emits a plain `FC_UP` with no allocation-override flags rather
than reproducing the vendor's undocumented 0x20 pointer-attribute bit; the recovered
semantic contract is a nullable MIDL-allocated `wchar_t*` output. This is an owned
interpreter description, not an assertion of byte-for-byte descriptor identity.

Return type on primary server ops 0–19: **i64** (`FC_HYPER`, IsReturn), not a caller
output-pointer argument. `NdrClientCall3(..., pReturn=NULL, ...)` returns it in the
client-call result. Managed `ThrowIfError(int64)` tests **nonzero**, converts to i32
and throws `Win32Exception(code, FormatWin32Message(code))`; this is **Win32 status,
not HRESULT success/failure semantics**. Pre-call errors are 87 (ERROR_INVALID_PARAMETER,
null argument) and 6 (ERROR_INVALID_HANDLE, null client handle).

Correction vs task assumptions: the previously assumed "5=LockOnLeave, 10=Wake, 13=Pause"
came from name-order guessing; the true wire opnums are **11, 8, 16** respectively.
Getters requested (capability/version/all settings) = ops 5, 4, 6.

Stack offsets (x64, ctx at 0): single-arg setters `[in] u32` at offset 8, ret at 0x10;
GetVersion/Capability out at 8, ret at 0x10; GetAllSetting outs at 8..0x78 (15 × u32),
array pointer at 0x80, ret at 0x88; op0 binding at 0, out-ctx at 8, ret at 0x10.

GetAllSetting field order (managed wrapper + registry cross-check): p1 Capacity, p2
SensorType, p3 ApproachEnabled, p4 ApproachDistance, p5 ApproachDistanceAutoAdjust,
p6 PresenceLeaveEnabled, p7 PresenceLeaveWaitTime, p8 PresenceLeaveCameraAssist,

the allocated wide-character array. The exported V1/V2 clients ignore its content
and free it via their MIDL free routine; the owned client does the same.

Capacity (p1) is projected to a bool by the managed getter; it is not the op-5
capability bitset. Managed nullable fields use op-5 bits: SensorType=0x1,

LeaveWait=0x20, CameraAssist=0x40, LeaveDistance=0x80, LeaveAutoAdjust=0x100,

## 5. Client object layout & lifecycle (from Initialize/Close disasm)

- `HPDRpcClientInitialize`: allocs 32 B client object; `RpcStringBindingComposeW` +
  `RpcBindingFromStringBindingW` store binding at obj+0; op0 stores returned ctx at obj+8;
  callback stored obj+0x10/obj+0x18. `*rpcClient = obj`.
- All getters/setters: thunk does `NdrClientCall3(PROXY_INFO @0x17ea0, nProcNum, 0,
  obj->ctx, …)`.
- `HPDRpcClientClose` (op1, ctx [in,out]) then frees obj; `HPDFree` is a plain heap free.
- Callback push path: op2 registers the token. The shared record at PS+0x428
  uses `FC_CALLBACK_HANDLE`, callback op 0, one `[in] i64` token and no return.
  Client MIDL_SERVER_INFO @0x17d60 uses FSO @0x17964 (0x428) and callback function
  @0x18530 → 0x15f0, which invokes the callback stored in the client object.
  This is a callback on the existing binding, not a second registered endpoint.
  The owned settings client does not register it or claim a live presence stream.

## 7. Implementation note for the Rust client (no vendor DLL, rpcrt4 only)

1. `RpcStringBindingComposeW(NULL, L"ncalrpc", NULL, L"HumanPresenceDetectionEndpoint",
   NULL, &str)`; `RpcBindingFromStringBindingW`.
2. op0 with the binding as `handle_t` → receive ctx handle.
3. Writes: op 11 / 8 / 16 (etc.), ctx + `[in] u32`; native settings read via op 6
   (15 u32 + allocated wchar array, always free it) and capability via op 5.
4. Generate our own NDR32 proc/TFS descriptors from §3 semantics per the repo generator
   conventions (`OI_HAS_RPCFLAGS|OI_USE_NEW_INIT_ROUTINES`, EXTS64, 6 B OIF params,
   `FC_BIND_CONTEXT` handle descs); no vendor bytes are embedded — the byte-identical
   verification above is evidence only, and descriptor regeneration follows
   `crates/lctrl-hal-win/src/ndr/{mod,dolby,elevoc,hpd}.rs` practice. Constant buffer
   fields are conservative interpreter sizing hints generated per parameter class;
   the conformant output sets ServerMustSize and robust client correlation checking.
5. Enum domain values: Near/Middle/Far = 0/1/2, Short/Mid/Long = 0/1/2, bools 0/1
   (managed enum dump, session SenseRe.jsonl line 214; mirrored by live registry
   `…\SmartSense\Parameters\HPD` values).

Implemented source: `crates/lctrl-hal-win/src/sense_rpc.rs` owns lazy binding,
context open/close, version/capability/aggregate getters, typed setters and RPC-only
SEH conversion. `ndr/hpd.rs` generates the used descriptors at compile time.
`sense.rs` routes six HPD settings to RPC and keeps privacy-alert/attention-tracking
on their distinct legacy pipe. There is no HPD pipe fallback after an RPC failure.
`SenseFeature::rpc_command` maps wake/approach-distance/leave/leave-wait/leave-distance/
video to 8/9/11/12/14/16; all RPC bools use 0/1. `sense status` projects optional
fields using op-5 capabilities. Writes poll only the changed feature in the
independent registry store (10 attempts, 50 ms between misses), not unrelated
metadata that differs between RPC and registry. CLI dry-run and auto-restore use
the same normalized state and existing transaction path.

## 8. Native read / write / restore smoke procedure (not executed here)

Prerequisites: parent has reconciled target SSH health; use the exact source-bound
x64 Windows build and record its source manifest/binary hash. Run from an elevated
authorized owner seat, keep the HPD driver/server and SmartSense service installed,
and do not disable Vantage or any service to make this path appear successful.
Retain stdout/stderr, native exit codes and independent read receipts for every step.

1. Read-only admission: run `vantage --json sense status`. A source-bound diagnostic
   consumer may additionally call `NativeHpdRpc::version()` and `capability()`; record
   the full u64 capability result. Compare supported normalized fields against a
   separate PowerShell `Get-ItemProperty -LiteralPath
   'Registry::HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\SmartSense\Parameters\HPD'`
   read. Capture PresentLeave, LeaveDistance, LeaveWait, Approach, ApproachDistance,
   Video, Capability, SensorType and FacialFeatureRegistered before any write.
   Refuse a write when its RPC field is absent or its independent baseline is unknown.
2. For one owner-authorized adjacent toggle at a time, choose the inverse of its
   captured baseline. Example when Video=1: `vantage --json --dry-run sense pause-video off`.
   Verify the independent registry snapshot is unchanged after dry-run.
3. Commit the same request (`vantage --json sense --yes pause-video off` in that
   example). Before restoring, independently read the registry and require Video=2;
   require `vantage --json sense status` to report pause_video=false. A zero RPC status
   or CLI exit alone is not acceptance. If either read differs, retain both receipts
   and proceed to restoration rather than replaying the forward write.
4. In a `finally`-equivalent cleanup, restore the exact original toggle with the CLI
   (example baseline Video=1: `vantage --json sense --yes pause-video on`). Independently
   require both Video=1 and RPC pause_video=true after restore. Confirm all other
   captured settings are unchanged. If the native child/transport outcome is unknown,
   reconcile it before an outer restore; do not issue overlapping writes.
5. Repeat separately for lock-on-leave (op11, PresentLeave 0/1) and wake-on-approach
   (op8, Approach 0/1), with owner consent for potential locking/waking. Optional
   distance/wait acceptance uses known 0/1/2 baselines and restores those exact raw
   selectors. The existing `--auto-restore` path can then be exercised as a separate
   transaction smoke, not substituted for an independently observed midpoint.
