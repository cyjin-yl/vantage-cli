## 6. Our bounded equivalent — implemented behaviour (unchanged)

`crates/lctrl-core/src/diagnostics.rs:13-20` defines the item enum
`DiagnosticKind = Battery | Thermal | Storage | Memory | Firmware | Network`;
`:28-36` the outcome enum `Passed | Failed | Skipped | Warning | Unavailable | Cancelled |
ResourceError`; `:337` `DEFAULT_DIAGNOSTIC_ITEM_DEADLINE = 5 s`; `:339-343`
`DiagnosticRunOptions { cancellation, per_item_deadline }`; `:378-396` the status snapshot
(`Idle|Preparing|Running|Completed|Cancelled|ResourceError`, run id, current item, counts) —
the same state names the vendor state machine uses.

`crates/lctrl-hal-win/src/diagnostics.rs`:
`diagnostic_items()` (52-60) returns those six items; `diagnostic_query()` (531) fixes one
public WQL query per item; each item gets one evaluator (`evaluate_battery` 828,
`evaluate_thermal` 923, `evaluate_storage` 1042, `evaluate_memory` 1094,
`evaluate_firmware` 1138, `evaluate_network` 1179); execution is serial through a single
bounded worker with a one-job queue (extra callers rejected, not queued into parallel WMI
reads), cooperative cancellation, per-item deadline, and skipped/cancelled/resource-error
results for the remainder. Nothing there touches the vendor addin, `LdeApi`, `lsdk.dll`, or
any diagnostic driver; `Dependency::LenovoDiagnosticsDriver` is declared as a vendor switch in
`crates/lctrl-core/src/command_capability.rs:502` but **no command capability requires it**
(`grep Dependency::LenovoDiagnosticsDriver` in `crates/lctrl-hal/src/` returns nothing), so
`scan.list`/`scan.run` keep `PublicWin32Cim` + `LinuxDiagnosticTools` only.

### Per-item definitions (issue #35 criterion 1)

| item | public check | measurements | pass / fail rule | declared limits |
|---|---|---|---|---|

The six item names deliberately keep the inventory vocabulary of the earlier
implementation (issue #35 criterion 1) instead of the vendor component names: our checks are
WMI record evaluations, and renaming them to `Audio`/`Camera`/… would imply interactive
vendor tests we do not run.

## 8. Non-claims (issue #35 criterion 4, charter §1)

- **No LdeApi JSON compatibility is claimed.** `LdeApi.JsonObjects.TestResult` field-level
  schema was not recovered (see §3.3); our result model is `DiagnosticResult`
  (`kind`, `outcome`, `detail`, `source`, measured `name/value/unit` pairs, `threshold`,
  structured `reason`). Anything asserting LdeApi schema parity would be false.
- The vendor addin, `LdeApi*`, `lsdk.dll`, `ldiag_api.dll`, `smartmontools.zip`, module
  binaries and `LenovoDiagnosticsDriver.sys` are **not** executed, loaded into a process, or
  decompiled, and none of them is added to this repository or referenced by any crate. The
  recon read on-disk metadata only: version resources, `PackageMetaData.xml`, and UTF-16
  string tables from a temporary read-only scratch copy on the operator host (since deleted).
- No destructive test (memory stress, disk write/scan, bad-sector repair), no adapter
  enable/disable, no service mutation, no reboot, no scheduling.
- `scan` still reports `Available` for a *bounded inventory-and-status* diagnostic; deep
  vendor tests are reported as unavailable per item, never as a pass.

## 10. Remaining decisions (parent)

1. **Item granularity.** Extending `DiagnosticKind` to the vendor component list would change
   a public `lctrl-core` type, both HALs, the CLI surface and the persisted capability matrix.
   Recommendation: keep the six items and cite §7 as the coverage statement.
2. **`scan status` / `scan cancel`** are named in issue #35 and exist in vendor form
   (`Get-Status`, `Cancel-Scan`). Our HAL exposes `diagnostic_status()` and in-run
   cooperative cancellation, but a fresh CLI process always sees `Idle` and there is no
   out-of-process cancel path (no daemon route carries diagnostics:
   `crates/vantage-daemon/src/*` has no `Diagnostic` reference). Implementing the pair needs
   a daemon-mediated run; that is a surface/ownership decision, not a repair.
3. **Per-item definitions in output.** §6's table lives in this document; surfacing it from
   `scan list` (e.g. `--verbose`/extra JSON fields) would change the CLI output contract and
   was not done without approval.
