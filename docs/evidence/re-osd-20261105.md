## 2. The pinned toggle target (proven)

User preference lives in two DWORDs under the service key, and the *only* write path
the vendor UI uses is a user-defined service control code on
`LenovoFnAndFunctionKeys` — not a direct registry write, not a WMI class, not an
`OSDControl.exe` argument:

| indicator | control code (on) | control code (off) | registry value written | value semantics |
| --- | --- | --- | --- | --- |
| CapsLk OSD | `146` / `0x92` | `147` / `0x93` | `HKLM\SYSTEM\CurrentControlSet\Services\LenovoFnAndFunctionKeys\VantageToast\ShowCapslkOSD` **and** `...\ControlShowOSD\ShowCapsNumlkOSD` | `1` = indicator shown, `0` = suppressed |
| NumLk OSD | `148` / `0x94` | `149` / `0x95` | `...\VantageToast\ShowNumlkOSD` | `1` = shown, `0` = suppressed |

Related but **out of scope** (Vantage toast, not the Fn OSD): `144` / `0x90` and
`145` / `0x91` = `SetFeedback(Success)` / `SetFeedback(NeverPop)`, which write
`...\VantageToast\NeverPopToast`.

State read is a plain registry read of `ShowCapslkOSD` / `ShowNumlkOSD`
(`1` ⇒ On, anything else ⇒ Off); the vendor verifies its own writes by polling that
value 10 × 200 ms after the control call.

## 3. Proof — managed side (`IdeaKBDManagerAddin.dll`, IL via `monodis`)

`IdeaKBDManagerAddin.ToastUtils.HotkeyServiceInvoker` (literal fields at typedef 6):

- `HOTKEY_SERVICE_NAME = "LenovoFnAndFunctionKeys"`,
  `HOTKEY_UTILITY_PROCESS_NAME = "FnHotkeyUtility"`,
  `MINIMUM_HOTKEY_VERSION = "2.0.4.0"`, `CONTROL_SERVICE_DELAY = 0xc8` (200 ms).
- `InitHandle()` → `LibService.OpenServiceByName("LenovoFnAndFunctionKeys")`;
  every setter first calls `DoesLenovoHotkeysWork()` =
  `CheckHandle()` (service queryable, re-opened if not) **and**
  `DoesHotkeyProcessExist()` (`Process.GetProcessesByName("FnHotkeyUtility").Length > 0`).
- `SetCapsLkOSDStatus(status)` @ RVA `0x2400`: rejects any status outside
  `{On=0, Off=1}` ("Attempt to set to illegal CapsLkOSDStatus"), maps
  `0 → 146`, `1 → 147`, calls `NativeHelper.ControlService(handle, code, &status)`,
  then polls `GetCapsLkOSDStatus()` up to 10 times with 200 ms sleeps until it
  equals the requested status, and returns the observed status.
- `SetNumLkOSDStatus(status)` @ RVA `0x25c4`: identical shape, `0 → 148`, `1 → 149`.
- `GetCapsLkOSDStatus()` @ RVA `0x24e4`: gates on hotkeys working, not
  `IsFirstLanguageJP()`, and `DoesHotkeysVersionSupportCapsLkOSDControl()`; then
  `Registry.LocalMachine` → `SYSTEM\CurrentControlSet\Services\LenovoFnAndFunctionKeys\VantageToast`,
  `GetValue("ShowCapslkOSD")`; `value == 1 ⇒ On(0)`, else `Off(1)`;
  every gate failure returns `NotSupported(2)`. Log strings:
  `"ShowCapslkOSD: "`, `"Registry value ShowCapslkOSD does not exist"`,
  `"Exception thrown in GetCapsLkOSDStatus"`.
- `GetNumLkOSDStatus()` @ RVA `0x26a8`: same, value `ShowNumlkOSD`, gate
  `DoesSupportNumLkOSDControl()` @ RVA `0x276c` = `Capbility\SupportNumlkKey == 1`.
- `DoesHotkeysVersionSupportCapsLkOSDControl()` @ RVA `0x2800`: reads the service
  key's `ImagePath`, `FileVersionInfo::GetVersionInfo(path).FileVersion`, requires
  `>= 2.0.4.0`.
- `OSDStatusType { On = 0, Off = 1, NotSupported = 2 }`.

The Vantage UI contract that reaches this code is
`SystemUtilities.IdeaKBDManager.HotkeyOSD` → `IdeaKBDManagerAddin.ContractHandlers.HotkeyOSDHandler`:
`GetCapsNumLkOSDStatus(payload)` builds `OSDStatusResponse.OSDList = [OSDItem(CapsLk, GetCapsLkOSDStatus()), OSDItem(NumLk, GetNumLkOSDStatus())]`;
`SetCapsNumLkOSDStatus(payload)` walks `OSDStatusRequest.OSDList` and calls the
matching setter; `SetNeverPopOSDToast(payload)` = `SetFeedback(NeverPop)`.
The manifest declares `<Contract name="SystemUtilities.IdeaKBDManager.HotkeyOSD"/>`
and a `RegistryChangeEvent` subscription on
`...\VantageToast\PopToastCapsNumlkOSD` (the toast counter, not the enable flag).

## 6. Gates (and which ones this implementation applies)

- `Capbility\SupportNumlkKey == 1` → NumLk OSD control supported. **0** on 21VG, and
  the vendor UI therefore reports `NotSupported` for NumLk. The implementation keeps
  that gate: it reports `not_supported` and does **not** send `148/149`, even though
  the service accepts them (probe above) — the machine has no NumLk key
  (`Capbility\SupportNumlkKey=0`), so a "preference" for an indicator that can never
  be shown would be fabricated state.
- Service `ImagePath` FileVersion `>= 2.0.4.0` (installed: 2.1.2602.8) and
  `FnHotkeyUtility.exe` running. The implementation uses the effective proxy that
  the value must exist in the registry; the version/process checks are documented
  here rather than duplicated (a missing value is the observable failure the vendor
  also reports as `NotSupported`).
- Japanese UI language suppresses the CapsLk OSD inside `FnHotkeyUtility`
  (`"GetLanguageName is ja ,do not show osd!"`). That is a render-time rule of the
  OEM process, not a preference gate; the implementation does not replicate it.

## 7. Negative results — surfaces that are *not* the toggle

- `ControlShowOSD\ShowCapsNumlkOSD` is only a mirror written by codes `146/147`
  (and by the service's own product-info monitor thread); writing it directly does
  not notify the renderer. Not used as a write target.
- `OSDControl.exe` (SmartInteractAddin) is the AirGesture OSD: an MFC dialog app
  whose only control surface is window messages (`AIRGESTURE_OSD_FORCELYCLOSE`,
  `AirGestureOSDShow`), no registry preference and no CLI switch. Not a toggle.
- No master "OSD" switch exists in `HKLM\SOFTWARE\Lenovo` (full 3-level dump),
  `HKLM\SOFTWARE\WOW6432Node\Lenovo`, or `HKCU\Software\Lenovo`; the only
  OSD-named values on the machine are the five under the service key above.
- `SetNeverPopOSDToast` (codes 144/145) suppresses the Vantage *toast popup*, not
  the Fn OSD. Left out of `osd enable|disable`.

## 8. Implementation mapping

- `crates/lctrl-hal/src/osd.rs`: `OsdControl::fn_osd()` / `set_fn_osd()` plus
  `FnOsdStatus`, `FnOsdIndicator`, `OsdIndicatorState{On,Off,NotSupported}`,
  `FnOsdChange` — the pinned codes, value names and gates are carried in the
  public status so the CLI can print the contract it used.
- `crates/lctrl-hal-win/src/fn_osd.rs`: registry read (`RegGetValueW`), service
  open/control (`OpenSCManagerW`/`OpenServiceW`/`ControlService`), vendor-shaped
  verification (10 × 200 ms registry poll), rollback to the captured previous state
  on mismatch (`LctrlError::VerifyMismatch`). The `ControlShowOSD\ShowCapsNumlkOSD`
  mirror is read and reported next to the CapsLk indicator, never written.
- `crates/vantage-cli/src/lib.rs::execute_osd`: `enable`/`disable` now drive the
  Lenovo Fn OSD; `test`/`show` still paint the replacement overlay; `disable` also
  hides an active replacement overlay. `--dry-run` reports the current indicators and
  the codes that would be sent without touching the service.
- `crates/lctrl-hal/src/command_capability.rs`: `osd.enable`/`osd.disable`
  `Readback::Unverified → Required` (real readback + rollback),
  `FeatureBinding::Unprobed → Capability("osd.fn")`.

## 9. Unproven / inference

- **[INFERENCE]** `FnHotkeyUtility.exe` re-reads `ShowCapslkOSD`/`ShowNumlkOSD` at each
  CapsLk/NumLk event instead of caching them at start-up. Supported by the value
  names living in the renderer and by the vendor never restarting the process after
  a change; not observed — the visible OSD requires interactive session 1 and a real
  key press.
- **[INFERENCE]** The combined `ShowCapsNumlkOSD` flag governs the "CapsLock + NumLock"
  badge variant. Its write path is proven; its render-time use is not.
- Not attempted: `144/145` (toast), `SVC_CTL_SEND_UI_CAPSNUMLOCK_*` product-info thread,
  and any write to `ControlShowOSD` directly.
